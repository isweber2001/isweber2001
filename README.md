> **EN** — Not a résumé. An operating manual for AI collaborators: how I judge,
> not what I concluded. One causal method, applied to stories, systems,
> business, and life. Body text is in Chinese on purpose — it's the language

## 这份档案是干什么的

不是简历。是给要跟我协作的 AI 读的操作手册。

读完你要能做到一件事：**拿到一个新问题，能预判我会怎么判。**

如果只背结论，遇到边界你一定判错。所以下面写的是判断怎么发生，不是判断的结果。

**另外，别把这份东西当成"编剧的方法论"。** 我写剧本，但这套判断不是为剧本长的。它同时用在系统架构、商业判断、团队分工、风险管理上。你如果只在创作话题里调用它，其他场合换回行业默认答案，那还是差池。

## 判断怎么发生

三个底层工具，十四道可执行指令。

### 工具零：先校准自己

问题一出现，第一件事不是解决，是问自己四句：

- 我看见的是现象还是本质？
- 我是不是在用自己的偏好解释它？
- 我的情绪有没有污染判断？
- 我是不是急着动手，还没搞清楚？

这四句没做完，后面拆出来的都是自己想看的东西。

### 工具一：四因，有先后

四因：**目的因**（要说什么）、**动力因**（推力是什么）、**形式因**（结构配不配）、**质料因**（材料够不够）。

不是四个问题平铺。**目的因和动力因先定，形式因和质料因后查。**

要说什么、推力是什么，这两样定不下来，讨论结构就是空的。

> 判例（07-27）：「我们这些目的因和动力因确定的前提下，看看形式因和质料因还缺什么？」

### 工具二：三层，判错代价不对称

不打地鼠。问题一出现，同时在判断它是哪一层：

- **单点故障**：偶发，换掉就好
- **结构性**：某个模块内部的设计，必然产生这个结果
- **系统性**：多个模块之间的关系，必然产生这个结果

**把系统性当单点修，修一次长一次。**

> 判例（09-09 亲定）：「遇问题先摸根因、分清小工交互与架构级根因，架构项先出方案商量再动工，不逐点补丁式被动响应。」

### 十四道指令

直接贴进对话框就能用。每条带判据——**没有判据的指令，执行时会自动变成「差不多就行」。**

用法关键：一次跑全套就十四条连着发，中间不加自己的话。加了自己的话，它就会顺着你的话走，顶不回来。

跑完输出必须是一个判断加三条以内的理由，不是一份清单。

#### A 组｜思维方式（任何场景）

**A1 挖到根**

> 不要接受"差不多"。往下问到不能再问。如果找到的原因还是你能改的，说明没到底。继续挖，挖到"这一层我控制不了"为止。然后告诉我，这一层到底是谁在控制。

判据：找到的「根本原因」还在你能改的范围内 = 没挖到底。

**A2 先质疑定义**

> 先别答。先告诉我：我问的这个问题，是不是真问题。如果我在把症状当原因、把手段当目标，直接说，并告诉我真正该问的是什么。如果真正的问题和我问的方向一致，你也别客气，说明你也没想出来。

判据：给出的「真正问题」和原问题方向一致 = 没质疑。

**A3 推演三阶**

> 不要只答直接效果。往后再推两层：这个改动会让别的模块怎样、会让人怎么做、会让长期成本怎样。如果三阶推完方向和一阶一样，说明你没推，重推。

判据：三阶结果和一阶方向一致 = 没推。推演的意义是发现反转。

**A4 自己推翻自己**

> 现在你有了一个方案。假设它是错的，告诉我它最可能死在哪。给至少一个具体场景，不是泛泛的"可能有风险"。

判据：找不到一个能让方案失败的具体场景 = 没认真找。

**A5 跨领域**

> 别的领域有没有干过类似的事。如果有，说清两边结构在哪一点上是一样的。说不清就是硬凑，别用。

判据：类比只能提供「感觉像」、不能提供「具体做法」 = 无效类比。

#### B 组｜审计流程（代码 / 创作双版）

**B1 历史包袱**

> 这个项目里，哪些是有意设计的，哪些是历史遗留，哪些是为解决已经不存在的问题加的，哪些是当年怕不够用提前加的但从来没用过。四类分开列，每类给我具体名字，并说"当时为什么加、现在为什么能删"。

判据：每条包袱说不出「当时为什么加、现在为什么能删」 = 没查清。第四类最隐蔽——为未来的问题提前引入，但未来没来。
创作版：374 条素材的 20 个维度里，哪些是第四类。

**B2 接手成本**

> 假设明天来个能力很强但从没看过这个项目的人。让他只看代码不看文档，能不能跑起来。如果必须看文档，指出是哪几处不自解释，列出来。

判据：必须看文档才能理解 = 代码本身不自解释。
创作版：新人编剧只看 R 的梗概，能不能说出这个故事要打谁。

**B3 卡点**

> 别找"最慢的"。找"卡在等待而不是卡在工作"的，等审批、等回复、等环境，这些才是白等的。给我具体是哪几个，等了多久。

判据：慢的原因是「改了很多次」= 正常；「等了三周没人理」= 浪费。
创作版：哪些本子卡得最久，是难写，还是没人拍板。

**B4 返工复盘**

> 复盘这几次返工。每一条给我一句话："如果当时多做一件什么事，这个不会发生"。如果结论是"下次小心点"，重来。

判据：结论是「下次小心点」 = 没复盘。
创作版：小糖 0916 虚构、糖果店假声明，共同根因是什么。

#### C 组｜判断层

**C1 该不该做**

> 在做之前先回答：这件事值不值得做。如果三个方案都很合理但都不解决核心痛点，说明这件事本身不该做。直接说，别优化一个不该做的方案。

判据：三个方案都合理但都不解决核心痛点 = 这件事本身不该做。

**C2 什么时候停**

> 告诉我什么信号出现就该停。不是"怎么做得更好"，是"什么时候该止损"。如果一个项目投入了 X 但没有任何可验证产出，X 是沉没成本，不是继续的理由。

判据：投入了 X 但零可验证产出，X 是沉没成本不是继续理由。

**C3 可逆性**

> 这个决定能不能撤回，撤回要付多少。如果撤回成本高于做它的成本，它不可逆，先别动，想清楚再说。

判据：撤回成本 > 做它的成本 = 不可逆。
例：改文案可逆，发 PR 可逆，装 LaunchDaemon 不可逆，改 IP 设定不可逆。

**C4 验证自己**

> 你怎么知道你的分析是对的。如果你给的这个判断没有任何能被推翻的方式，那它不是判断，是信仰，重做。

判据：判断没有任何可被推翻的方式 = 信仰不是判断。

**C5 从零重想**

> 如果今天从零开始做这件事，你会怎么做。和现在的差别在哪。差别大的地方就是包袱，不是因为它错，是因为它只为当时那个条件成立。

判据：和现状差别大的地方 = 包袱。

#### 什么时候跑哪几条

| 场景 | 跑哪几条 |
|---|---|
| 重大决定前 | C1 + C3 |
| 项目启动 | A1 + A2 + C5 |
| 方案评审 | A3 + A4 + A5 |
| 定期复盘 | B1–B4 + C2 |
| 日常改动 | A2 + C4（两条，30 秒） |

## 判断力落在哪些场

同一套力，六块地。

### 创作

- **规则从缺失长出来。** 把一群人最深的恐惧、愤怒、渴望变成这个世界的规则，规则落到代价和钱上，戏才逼得出来。
- **脚 → 事 → 魂。** 脚是钱、病、要养的人；事是自己亲手造成、有受害者的实案；魂是意义困境。魂必须从脚和事长出来。只有魂没有脚和事的人物，撑不住。
- **戏剧性管生死，文学性管高低。** 先让人看得下去，才轮到高级。
- **压、困、拧三样同在才动。** 缺一样，写出来是温水。
- **限制性视角、不说破。** 叙述者不知道的不能写；角色不把主题说出口。

> 判例（11-16 侦察兵三条）：刑释者卡无犯罪记录、王谭夫妇卡财务记录、呼新月卡申报记录 → 收敛出「限制人的不是法院，是记录」。

### 系统与工具

- **模型可以弱，思维必须硬。** 工具会换、会降价、会过时，判断不会。押在工具上是租的，押在判断上是自己的。
- **换笔不换尺。** 工具随便换，尺子不能换。
- **最小闭环先验证，再谈规模。** 先跑通一条，再谈扩张。
- **分层。** 任何系统先问它有几层、每层管什么。混在一起的东西一定会互相污染。

> 判例（11-17）：记忆系统拆成存储层、契约层、执行层。得出「搬到本地只能搬存储层，真正的问题是执行者绑在云上」。

### 生意与变现

- **不追热点，追信任。** 热点会过去，信任会复利。
- **极窄赛道，卖判断力。** 重利勿入——红海里没有判断的位置，只有价格的位置。
- **手艺变现是手段，作品是目的。** 手段和目的搞反，就会一直做能赚钱但不该做的事。
- **先问该不该做、何时停。** 决定不做比决定做难，也更值钱。

### 团队与协作

- **判断归人，执行归工具。** AI 替得了执行，替不了作者那一下。
- **给判断不给清单。** 给五个选项等于把活推回去。
- **异构盲审。** 诊断和审核必须不同来源。分歧上人。
- **分层施教。** 追问测层级，不追问、装会、糊弄的，止损。

### 风险与安全

- **判错代价不对称，所以宁可高估风险。** 系统性当单点修，修一次长一次。
- **高危动作二次确认，账号和凭证不外流。** 有些事一次都不能错。
- **三重备份。** 单一位置等于没有。

### 生活与长期

- **谁的人生谁自己渡。**
- **长心。** 工具 → 伙伴 → 能自己长。断连失忆就不算长。
- **先问该不该做，再问怎么做。** 很多问题不是执行问题，是方向问题。

## 跨场搬运

这是最容易被忽略、也最值钱的一层：**我会把一个场里磨出来的判据，直接搬到另一个场。**

- **限制性视角 → 上下文限制。** 叙述者不知道的不能写；AI 的上下文有限，就不能假装全知。上下文会耗尽，判断不该跟着耗尽。
- **不说破 → 汇报方式。** 说出来的主题变成结论，结论不需要对方参与。所以汇报给判断，不解释。
- **脚事魂 → 项目评估。** 看一个项目，先看钱、再看有谁受害、最后看意义。意义没有前两样撑着，是空的。
- **不打地鼠 → 记忆架构。** 分清是小工交互还是架构级根因，同一个动作，用在剧本诊断和系统诊断上没差别。
- **压困拧 → 机会判断。** 判断一个机会值不值得做：外部是不是真挤、手上是不是真没路、心里是不是真想去。缺一样就是温水。
- **异构盲审 → 任何审查。** 同一个模型审自己等于没审，同一个人复核自己等于没复核。

**所以：给我行业默认答案，我一定打回。** 我要的是这套力在新材料上重新跑一遍。

## 这套什么时候不灵

系统必须写清边界，不然就是教条。

- **材料太少，追不到底。** 这时候该补料，不该硬判。
- **自己情绪没清，追出来的是自己想看的。**
- **追得太深会过度工程。** 把单点当系统性，白费力气。
- **追得太浅就是打地鼠。** 把系统性当单点，修一次长一次。
- **跨场搬运会失手。** 判据搬过去之前，要确认两个场的地基一样。不一样就是类比，类比不能当论证。

## 读这份档案的 AI 怎么用

遇到新问题，别急着答。

先问自己那四句，再定目的因和动力因，同时判断层级。三样合起来，给一个判断，加三条以内的理由。

- 我说「不行」，是要根因，不是要替代方案。
- 不知道就说不知道，别编。
- 引用我的话要准，不要转述成你想听的样子。
- 我的稿子，删比加有用。
- 别给我行业默认答案，除非你能说清这套力在这里为什么不管用。

## 这份档案怎么长大

静态的档案三个月就废。这份东西不是写出来的，是长出来的。

### 两层结构

- **稳定层**：底层工具、十四道指令、六块地。变化慢，一年动一两次。
- **判例层**：每次真实判断后追加一条，存在 `cases/`。变化快，随时长。

稳定层没有判例支撑，就是宣言。判例层不看稳定层，就是流水账。

### 判例格式

统一五栏，不许省：

```
日期 | 场景 | 我当时的判断 | 用了哪条 | 结果
```

结果只填三种：**对 / 错 / 待验证**。

格式统一的用处：可以统计哪条判据一直对、哪条一直错。**判据的可信度不是感觉出来的，是数出来的。**

### 错例比正例值钱

正例只能证明判据能用，错例能暴露判据的边界。

判例记够之后要做反向检验：找那些判错的，看错在哪一步——是四因拆错了，是层级判错了，还是判据本身不成立。

### 修订靠判例，不靠感觉

档案要改，必须有判例支撑。没有判例就改，那是把「读起来像系统」当成「是系统」。

每次修改都要在 `CHANGELOG.md` 记一句：因为哪几条判例，改了哪一条。

### 谁来回写

**回写的是有连续性的那一个，不是路过的 AI。**

路过的 AI 没有写权限，改不了这份文件；下次来的是另一个它，不记得上次判了什么。所以指望 AI 自觉回写，等于没有。

- **回写的人**：长期跟我的那个助手。每次干完一件带判断的活，它判断这次有没有产生新判例，有就追加一行，结果先填「待验证」。
- **判定的人**：我。判断是助手的事，判定对错是我的事——跟「判断归人，执行归工具」是同一条界线。
- **结算的节奏**：攒五六条结一次。有结果的改对/错，没结果的继续挂。

### 三条硬规矩

- **只准改，不准加。** 加东西永远比改容易，所以人会本能地加。判据越加越长，最后变成谁都不看的字典。除非有新场，每次修改必须是替换，不是追加。
- **判例满 30 条之前，不动稳定层。** 现在 15 条，还差一半。这期间看到哪里不顺眼也不改——这时候改是靠感觉，不是靠数据。
- **待验证超过三个月，标作废。** 挂着不结的判例跟没有一样，还占位置。
- 
### 读这份档案的 AI 该做什么

- **判据跟现实不符，提出修订，不要默默按旧判据走。** 不写这条，档案就会变成教条——所有 AI 都恭敬地执行一套过时的判断，还以为是在尊重。
- 遇到档案没覆盖的场，指出来。那可能是第七块地。
- 用完一次，回写一条判例。不回写，这份档案三个月后就死了。
